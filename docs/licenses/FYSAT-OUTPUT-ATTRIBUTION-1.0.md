# FY-Sat Studio 输出数据来源署名：分层方案（v2.0）

> **文件定位（先读这句）**：本文件是**数据使用条款/请求**，**不是** FY-Sat Studio 软件许可证的附加条款，**不改变** `AGPL-3.0-only` 授予的任何权利。
> 重构说明：v1.0（2026-11-02 早间版）曾拟将「数据署名 + 附修改后源代码」作为 AGPLv3 §7 附加条款；经复核，**「数据附修改后源代码」不属于 §7 允许的六类条款**（详见 [`../../LICENSES.md`](../../LICENSES.md) §1.2），故 v2.0 重构为三层结构：软件许可层 / 数据条款层 / 技术元数据层。
> 版本 2.0 ｜ 2026-11-02 ｜ 配套文件：[`FYSAT-ADDITIONAL-TERMS.md`](FYSAT-ADDITIONAL-TERMS.md)、[`../../LICENSE`](../../LICENSE)

---

## 0. 三层结构总览

| 层 | 载体 | 法律性质 | 覆盖对象 | 强制力 |
|---|---|---|---|---|
| **L1 软件许可层** | [`../../LICENSE`](../../LICENSE) + [`FYSAT-ADDITIONAL-TERMS.md`](FYSAT-ADDITIONAL-TERMS.md) | `AGPL-3.0-only` + **仅 §7(b)(c)** 附加条款 | 本程序及修改版的分发 | **强制**（版权许可） |
| **L2 数据条款层**（本文件） | `FYSAT-OUTPUT-ATTRIBUTION-1.0.md` | 数据使用条款 / 请求（request） | ① 我们分发的数据（可强制）；② 用户自己生成的数据（仅请求） | ① 合同/使用条款可强制；② 无法律强制 |
| **L3 技术元数据层** | `src/fysat/provenance.py` + `src/fysat/export.py` | 技术实现（默认写元数据） | 所有导出的 TIFF/PNG | **默认执行**，无需用户操作 |

> 一句话：**软件许可管程序，数据条款管数据，技术元数据兜底**。三者互不越界。

## 1. 为什么这样分层（法律分析）

| # | 理由 | 说明 |
|---|---|---|
| 1 | **§7 只允许六类附加条款** | 与署名/来源/修改标记相关的是 §7(b)（保留合理法律声明/署名）与 §7(c)（禁止虚假来源、修改版合理标记）。「数据分发时附修改后源代码」不在其中；写进软件许可会被认定为 **further restriction**，接收者可依 §7 末段删除（§10 亦禁止进一步限制）。 |
| 2 | **§7(b)(c) 的对象是「程序材料」而非程序输出** | 条文原文针对 "that material"（你添加到覆盖作品中的材料）与 "Appropriate Legal Notices displayed by works containing it"。把「第三方分发数据必须标注」写成软件许可条件，超出条文对象范围，风险大于收益。 |
| 3 | **数据通常不是程序的衍生作品** | FSF 对 GPL/AGPL 的一贯立场：程序输出本身不因运行程序而受程序许可证约束。用版权许可去约束数据分发的效力天然较弱，不如用「数据使用条款 + 技术元数据」。 |
| 4 | **数据版权归属复杂** | 卫星数据可能涉及数据提供方（NSMC 等）条款，用户生成的数据版权归用户；我们不能用软件许可替用户的数据附加条件。 |
| 5 | **业务可行性** | 气象/科研用户需要自由使用、再分析、发表输出数据；若强制「随数据附源码」，会显著阻碍采用，且数据与源码并无一一对应关系，实际不可执行。 |

**结论**：把「数据署名」定位为「数据使用条款/请求 + 技术默认元数据」，而不是软件许可条款——既满足业务诉求，又不损害 AGPLv3 的合法性与下游兼容性。

## 2. 数据条款正文（适用于 **FY-Sat Studio 项目对外分发**的数据产品）

### 2.1 我们（项目方）的承诺

FY-Sat Studio 项目对外分发由其软件生成的数据产品（样例、官方处理结果、发布用图层等）时，**默认在数据元数据或随附说明中标注**：

| 字段 | 含义 | 示例 |
|---|---|---|
| `software` | 生成软件名称 | `FY-Sat Studio` |
| `software_version` | 版本号 | `1.0.0` |
| `license` | 软件许可证标识 | `AGPL-3.0-only` |
| `source_url` | 软件来源 URL | `https://github.com/lzh173/fysat` |
| `modified` | 软件是否被修改 | `yes` / `no` |
| `commit` | 源码提交（可得时） | `aec59f2` |
| `generated_at` | 生成时间（UTC） | `2026-11-02T00:00:00Z` |

### 2.2 对下游/再分发方的要求（**仅针对我们分发的数据**）

1. **强制（作为数据使用条件）**：再分发我们分发的数据产品时，须保留上述溯源字段，**不得虚假标注**软件来源、版本或修改状态。
2. **请求（非强制、非许可条件）**：若您对数据做了修改/再处理，请在元数据或说明中注明修改内容；保留 `source_url` 与 `commit` 便于溯源。

### 2.3 明确**不要求**的事项（避免误解与过度扩张）

- ❌ 不要求提供源代码（软件源码获取按 AGPLv3 §13/§6 处理，与数据无关）。
- ❌ 不限制数据的使用、再分析、发表、商业利用（除保留溯源字段外无其他条件）。
- ❌ 不构成对 AGPLv3 的任何补充限制；数据条款不改变软件许可。

## 3. 用户**自己生成**的数据：仅为请求（request）

- 我们**不主张**对用户用本软件生成的数据的任何权利，也不对其施加法律条件。
- **请求**（非义务）：保留默认写入的溯源元数据，以支持科研可复现性与数据流转追溯。
- 即使您删除这些元数据，也**不构成**对 AGPLv3 或本文件的违反（数据属于您）。
- 若您希望数据被下游正确引用，建议保留 `software / software_version / source_url / modified / commit` 字段。

## 4. 技术默认满足（L3）：导出元数据（**已实现**）

> 这是本方案中**可执行性最强**的部分：不依赖下游自觉，导出即写入。

### 4.1 字段清单（`build_provenance()` 产出）

| 字段 | 含义 | 说明 |
|---|---|---|
| `software` | 软件名称 | `FY-Sat Studio` |
| `software_version` | 版本号 | 取 `fysat.__version__` |
| `license` | 许可证标识 | `AGPL-3.0-only` |
| `source_url` | 软件来源 | 默认项目仓库，可用 `FYSAT_SOURCE_URL` 环境变量覆盖 |
| `modified` | 是否为修改版 | 仓库有未提交改动即 `yes`；取不到 git 信息时保守返回 `yes` |
| `commit` | 源码提交（短哈希） | 可得时写入 |
| `generated_at` | 生成时间（UTC，ISO 8601） | `YYYY-MM-DDTHH:MM:SSZ` |
| `generator_platform` | 生成平台 | 操作系统 + 版本 |
| `platform` / `instrument` / `level` / `product` | 数据观测属性 | 来自数据集元数据（若提供） |
| `observation_time` | 观测时间 | 来自数据集元数据（若提供） |
| `variable` / `source_file` / `reader` | 变量、源文件名、读取器 | 来自数据集/调用参数（若提供） |
| `extra` | 自定义字段 | 调用方可注入（如卫星/通道/产品号） |

### 4.2 写入与读取方式（实测代码行为）

| 格式 | 写入位置 | 实现 |
|---|---|---|
| **TIFF** | TIFF `ImageDescription` tag（单段可读文本，逐行 `key: value`） | `provenance.as_text()` → `tifffile.imwrite(..., description=...)`（`export.py::_write_tiff`） |
| **PNG** | PNG `tEXt` 块，键前缀 `fysat.`（如 `fysat.software`、`fysat.modified`） | `provenance.as_png_text()` + Pillow `PngInfo`（`export.py::_write_png`） |
| 读取（校验/下游） | — | `provenance.read_tiff_provenance()` / `read_png_provenance()` |

### 4.3 代码位置与默认行为

| 项 | 位置 | 行为 |
|---|---|---|
| 溯源收集 | `src/fysat/provenance.py`：`build_provenance()`、`as_text()`、`as_png_text()`、`read_*_provenance()` | 自动收集 Git/版本/平台/时间/数据元数据 |
| 导出接入 | `src/fysat/export.py`：`ExportOptions.provenance`（默认 `None`）→ 自动 `build_provenance()` | **TIFF 与 PNG 导出默认写入**，无需用户操作 |
| 自定义 | `ExportOptions.provenance` | 可显式传入字段覆盖/追加（GUI/CLI 可加业务字段） |

### 4.4 为什么这比「条款」更强

1. **自动执行**：默认开启，不依赖下游自觉或法律追责。
2. **随数据流转**：元数据嵌在文件内，转发/拷贝后仍在（除非用户主动清除）。
3. **不构成法律限制**：技术事实记录，不产生额外许可义务，不影响下游使用。
4. **科研价值**：`software_version + commit + generated_at + source_file` 直接支撑可复现性与引用规范。

## 5. 与 AGPLv3 义务的对应关系

| AGPLv3 义务 | 承接层 | 说明 |
|---|---|---|
| 分发程序时提供 Corresponding Source（§6/§13） | L1 软件许可 | 源码仓库公开 / 安装包书面要约 |
| 修改版软件分发须以 AGPL 提供源码 | L1 软件许可 | 由 AGPLv3 本身要求，**不需**写进数据条款 |
| 网络交互向用户提供源码（§13） | L1 软件许可 | 若未来提供网络服务，遵守 §13 |
| 署名与来源真实性 | L1 §7(b)(c)（程序）+ L3 元数据（数据） | 两处互补 |
| 数据署名 | L2 数据条款 + L3 技术元数据 | 非软件许可条款 |
